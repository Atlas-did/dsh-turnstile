# 页面搭建器：编辑历史与可视化回退

## 用户看到什么

页面搭建器左侧在「快照」之后增加「编辑历史」。每次已经提交的添加、删除、移动、属性或样式修改都会留下：

- 时间；
- 人话标签；
- 对应的完整页面状态；
- 当前所处步骤的高亮。

点击任意历史步骤，画布、属性面板、撤销和重做一起回到该状态。选中节点已经不存在时，选择回退到根节点，不留下无效检查器。

## 为什么保留两套结构

`page-model.js` 的 `stack.past` / `stack.future` 继续负责逐步撤销和重做；`history-timeline.js` 负责带时间和标签的任意步骤跳转。时间线不是另一份只读日志，也不是对命令栈的替换。

所有普通编辑统一经过 `builder.html` 的 `commit(cmd)`：

1. `M.run(stack, cmd)` 生成不可变的新页面；
2. 同步选中节点；
3. `H.append(...)` 记录页面副本、类型、标签和时间。

点击历史步骤后，`syncStackToTimeline()` 用时间线游标重建命令栈：

- 游标之前的状态成为 `past`；
- 当前状态成为 `current`；
- 游标之后的状态成为 `future`。

因此回退后的新编辑会同时清空命令栈的未来并截断时间线的旧未来，不会出现画布与撤销方向不一致。

## 基线与快照

- 初次打开：历史从「空白画布」开始。
- 套用模板：模板成为一个新的编辑基线，模板内部的构建步骤不冒充用户逐步编辑。
- 保存：只更新当前页面的 `meta.pluginName`，不制造编辑历史。
- 刷新并恢复：历史从唯一的「已保存页面」基线开始；未保存的旧时间线不跨刷新伪装成已保存内容。
- 原有快照继续可用。能匹配到时间线状态的快照走同一跳转逻辑；超出时间线容量的旧快照成为明确标记的新基线。

## 验收

`npm run test:builder` 使用系统 Edge 和真实鼠标／表单操作，覆盖：

- 历史行包含时间和人话标签；
- 连续属性修改产生连续步骤；
- 点击早期步骤后画布实际回退；
- 回退后撤销、重做仍按时间线移动；
- 回退后新编辑截断旧未来，旧分支不再列出；
- 多选后的批量修改只增加一个历史步骤，并能整体撤销／重做；
- 保存、真实刷新、恢复同一页面，历史重置为一个基线；
- 无未捕获浏览器脚本错误。

当前结果：**61／61 通过**。批量编辑契约见 `docs/151-builder-multi-select.md`；大纲选择、折叠和键盘操作见 `docs/152-builder-outline-keyboard.md`。选择、折叠和焦点变化不会进入历史，Delete 与删除按钮共用同一个原子命令。

这些证据来自隔离副本、临时 HTTP 服务和浏览器夹具，**不等于真实 mini 或桌面端端到端验收**。
