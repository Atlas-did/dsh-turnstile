# 计划初稿：DSH 环境治理体系（2026-10-31 夜）

> 状态：**初稿，未定稿**。按用户要求，下一步是 grill-me 盘问 → 定稿 → 子 agent 独立审核 → SDS。
> 本文件只记录「打算怎么做」，不含任何已完成声明。

## 一、为什么要有这个计划（今天的三个失败）

| 失败 | 事实 | 根因 |
|---|---|---|
| AA 连不上，我判成「版本不匹配」 | 版本确实是其中一层（2.0.2 vs 2.1.0），但最后一层是**本机代理掐断出站** | 我从没测过出站连通性，工具里也没有这一项 |
| 装插件要 npm pack + 手工拷贝 + 改 bundles | 一个 `git+https` 依赖让 `pnpm add` 整条失败 | 依赖可解析性没人管 |
| 两个市场插件同装 | 我按教程装了第二个，没先查用户已有什么 | 没有「装之前先看现状」的前置检查 |

共同点：**我的工具全是静态检查（profile 文件、patch、engines），没有一条会测运行时与外部链路**。

## 二、目标形态（一段时间内只做这一件事）

```
node tools/diagnose.mjs            ← 一条命令说清「现在坏在哪、下一步做什么」
        期望输出：
        ✓ 环境   DSH 2.1.0 / 插件 2.1.0 / npm latest 2.1.0
        ✗ 出站   agents-anywhere.com 直连 422 / 7897 ConnectError / 31181 未运行
        ✗ 代理   ALL_PROXY=7897 对所有 HTTPS 失败（google 000, deepseek 401 通）
        → 修法   把 agents-anywhere.com 写入 NO_PROXY 并重启 AA（已做过一次）
```

配套：控制台「环境管家」页显示同一份结果（今天已有只读版，见 docs/85）。

## 三、分阶段（每阶段都必须有夹具 + 可验证输出）

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | `tools/diagnose.mjs` 骨架：出站探测（多路径）+ 版本矩阵 + 日志摘要 | 用手造的三个坏夹具（代理挂/版本旧/日志报错）各跑一次，输出必须命中 |
| P2 | 日志解析器：AA `runtime-*.jsonl` + 插件 `dsh-runtime.jsonl`，抽 ERROR 并归类 | 今天这份 395KB 真实日志能复现「PARSE_ERROR → 版本」「ConnectError → 代理」两条结论 |
| P3 | 环境管家面板接入 diagnose（只读展示 + 复制命令） | e2e：面板显示三条结论中的至少两条 |
| P4 | 流程降复杂度：依赖可解析性检查（git 依赖必须本地化）、装前现状快照 | 装第二个市场前会先报「已有 dshmarket」 |
| P5 | 全部坑固化成回归：NO_PROXY、双市场、client bundle 加载、版本不匹配 | 每个坑一个夹具，跑一次全绿 |

## 四、明确的非目标

- 不再新增「只查 profile 静态文件」的工具（已有的够了）
- 不修第三方插件的代码（除 sidebar 两个按钮的 CSS，已带备份）
- 不做商店合规优化（用户已明确：功能优先）

## 五、风险

| 风险 | 应对 |
|---|---|
| 出站探测被代理/防火墙干扰导致误判 | 每条探测记录「路径 + 结果 + 耗时」，不合并成一个布尔 |
| 日志格式随版本变 | 解析器只认 `event`/`level` 字段，未知格式降级为原文摘要 |
| 又变成「工具越长越多」 | 只允许一个入口 `diagnose.mjs`；子能力是模块不是新命令 |

## ⚠️ 本稿已被第 1 轮审核推翻两处（见 docs/92）

1. **「最后一层是代理」不成立**：NO_PROXY 之后 AA 仍报错，真实错误是 `codex-cli 0.134.0` 与 AA 2.1.0
   connector 的 `unknown variant 'recency_at'` 协议不兼容（222 条，已复核）。DSH 那一路已通，Codex 那一路未修。
2. **12 格连通性矩阵作废**：实测假阳性 75%（github 直连 000 是大陆基线；31181 的两格是我 curl 没带 CA）。
   改为「1 个受害进程 × 它真实走的路径，一次只排除一层，直到出现真实成功响应」。
