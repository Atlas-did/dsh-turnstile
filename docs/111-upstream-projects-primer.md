# 上游项目原始功能详解（我们抽了什么、为什么这么抽）

> 目的：说明每个参考项目**原本是干什么的**，它的核心模型是什么，我们再从中抽了哪一层。
> 标注规则：`✅` = 我自己核过/行业公知；`⚠️` = 按通用原理复述、未逐一核对源码。

## 1. WinMerge —— Windows 上的文件/文件夹对比与合并

**它是什么**：开源（GPL）的差异比较工具，最初是 Windows 上的 WinDiff 替代品，后来长成「对比 + 三方合并」工作台。

**原本的核心功能**（✅）：

| 能力 | 说明 |
|---|---|
| 文件对比 | 行级 diff，左右并排，差异高亮、行内差异（字符级）高亮 |
| 三方合并 | 左/中/右三栏，把两个版本合进第三个文件，逐块接受 |
| 文件夹对比 | 递归比较，按大小/时间/内容判定，可生成 patch，可复制/删除差异项 |
| 过滤 | 行过滤器、文件过滤器、正则过滤，排除噪声（日志时间戳之类） |
| 差异选项 | 忽略空白、忽略大小写、忽略行尾、忽略「移动的块」（moved blocks） |
| 表格/二进制/图片 | CSV 表格对比、二进制对比、图片像素与叠加对比 |
| 插件与集成 | 7z/压缩包、版本控制集成（SVN/Git） |

**它的核心模型**：差异不是「一串行号」，而是**每一行的状态**——未变 / 新增 / 删除 / 被移动 / 仅空白不同。
选项决定「哪些差异算差异」，所以同一个文件在不同选项下结论不同。

**我们抽的是哪一层**：不是 UI，是**「状态编码」**。我们把它压成位域（一个整数里 8 个正交位）：
新增 / 删除 / 配置变了 / 位置变了 / 仅文本变 / 仅结构变……
好处：两次采样之间「变了什么」可以用一次位运算比较，而不是逐字段 diff（`lib/diff-state.js`）。

**在 mini 里的意义**：装完插件 → 采一次 → 再装一个 → 采一次，**一眼看出这次动了哪几处**，而不是重新读一遍全表。

## 2. TreeNew —— 只画可见行的树控件（源码已核对）

**来源**：System Informer 的 `phlib/treenew.c`（10,753 行 / 332,090 字节），2026-10-31 逐行核对。

**原本的核心功能**：

| 机制 | 源码证据 |
|---|---|
| 只画可视行 | `PhTnpPaint`（7682 行）用 `(top - HeaderHeight) / RowHeight` 算首末行，只遍历这段 |
| 几何按范围算 | `PhTnpGetRowRects`（5842 行）：`(Start - VScrollPosition) * RowHeight`，**固定行高**，O(1) |
| 只失效变化区域 | `PhpTnpInvalidateRows`（163 行）与内容矩形求交后失效 |
| **整树拍平** | `Context->FlatList` 是真数组；结构变化时 5409 行 `PhClearList` + 逐个子节点重新插入 |
| 子节点从回调来 | `PhTnpGetNodeChildren`（5266 行）经 `PH_TREENEW_GET_CHILDREN` 向应用要 |

**修正我之前的说法**：我原先写「模型是树、不是预扁平化数组」——**错了**。它确实拍平成数组，
每次结构变化 O(n) 重建；真正省下的是**绘制与几何 O(可视行)**。取舍是「拍平一次，换 O(1) 定位」。
���原理与它的设计目标复述。

**它解决什么**：普通树控件为每个节点创建一个 UI 对象。节点上千时，创建/布局/滚动都变慢，内存也爆。

**核心机制**（⚠️ 通用原理）：

1. 数据与视图分离：节点数据放在数组/树结构里，UI 只创建**可视区域**那几十行；
2. 滚动时**复用**行对象（而不是销毁重建），只换内容；
3. 需要知道总高度 → 用固定行高或测量缓存；
4. 展开/折叠只改「可见索引区间」，不重建整棵树。

**我们抽的是哪一层**：可视区间计算 + 行复用（`lib/virtual-window.js`），配 200 节点 fixture 做回归。

**在 mini 里的意义**：桌面端 1200+ 架构节点，滚动不掉帧；节点再多也只是「换内容」不是「建对象」。

## 3. wxFormBuilder —— wxWidgets 的可视化界面设计器

**它是什么**：开源的 wxWidgets GUI 设计器（C++/Python/PHP 代码生成）。

**原本的核心功能**（✅）：

| 能力 | 说明 |
|---|---|
| 对象树 + 属性检查器 | 左侧控件树，右侧属性网格（每个属性有类型、默认值、枚举） |
| Sizer 布局 | 盒式/网格/弹性空间，设计器里直接表达「拉伸与对齐」 |
| 代码生成 | 输出 C++/Python/PHP/XRC；**生成代码与手写事件代码分离**，重新生成不覆盖你的逻辑 |
| 撤销/重做 | 命令模式（command stack），每步可逆 |
| 工程文件 | XML 描述，可 diff、可版本管理 |

**我们抽的是哪一层**：**命令栈 + 快照策略**。很多设计器只有 undo/redo（一步步退），我们保留「某个时刻的完整快照」，
所以既能退一步，也能跳到某个历史点（`lib/designer-ops.js`）。

**在 mini 里的意义**：设计器里改坏了，不用重来；而且能对着历史快照说「就是这一步之后坏的」。
## 4. Designable —— 表单/页面搭建器（阿里，基于 Formily）

**它是什么**：一个可搭建「表单/表格/图表/应用」的设计器框架，本身不做业务组件，只提供**搭建这回事**的基础设施。

**原本的核心功能**（✅ 结构层面；具体 API 名以文档为准）：

| 层 | 内容 |
|---|---|
| Engine | 引擎：操作注册（operation）、选中、历史、拖拽接入 |
| Workspace | 画布：承载组件树，处理落点与嵌套 |
| Panel | 面板：设置面板、大纲树、工具栏 |
| Component | 组件包装：把普通 React 组件包成「可设计」的，声明它能不能被拖、被选中、改大小、被放置 |

**它最出名的两点**：

1. **组件自己的能力由组件自己声明**：一个组件可以声明「我不可拖拽、但我可被放置」；设计器只读声明，不猜。
2. **设置面板由 schema 生成**：字段一改，面板自动多一行控件，不用改设计器代码。

**我们抽的是哪一层**：① 能力约束（`lib/capabilities.js`）② 历史时间线（`lib/history-timeline.js`）。

**在 mini 里的意义**：插件没声明位置配置时，我们**不给你画拖拽手柄**——省掉「拖了没反应」这类浪费。
历史做成**并行面板**而不是替换 undo：看的是「什么时候变的」，不是「再退一步」。

## 5. LowCodeEngine —— 低代码引擎（阿里）

**它是什么**：一套「低代码平台的地基」，不提供具体业务，只定义协议与扩展点。

**原本的核心功能**（✅）：

| 概念 | 说明 |
|---|---|
| Schema 协议 | 用 JSON 描述页面：组件树 + 每个节点的 props + 生命周期 |
| 资产包（assets） | 组件（materials）、属性设置器（setters）、插件（plugins）三类，可独立发布 |
| 设计器 | 画布 + 大纲树 + 设置面板 + 工具栏，设置面板用 SettingTarget/SettingField 组织 |
| Selector | 画布的选中态抽象，可多选，可订阅 |
| 模拟器 | 在沙箱里跑真实渲染，保证「所见即所得」不靠猜 |
| 插件化 | 一切皆插件：撤销重做、快捷键、大纲、设置面板都能换 |

**我们抽的是哪两层**：① 多选/批量写（`lib/selection.js`）② Setter 注册表（`lib/field-schema.js`）。

**在 mini 里的意义**：一次改 20 个插件的位置（而不是点 20 次）；新增一种属性，只要注册一个 setter，面板自动长出控件。

## 6. Formily —— 表单解决方案（阿里）

**它是什么**：面向复杂表单的「schema 驱动」方案，解决「字段多、联动多、校验多」的表单。

**原本的核心功能**（✅）：

| 能力 | 说明 |
|---|---|
| JSON Schema 驱动 | 一份 schema 渲染整张表单，字段类型决定控件 |
| 路径表达式 | 用 `x-path` 定位字段、读写、联动（`{{}}` 表达式） |
| 响应式联动 | 字段变了 → 依赖它的字段/显示状态自动更新 |
| 校验 | 内置规则 + 自定义校验，schema 里声明 |
| 多端适配 | 同一 schema 换 antd/fusion 组件库 |

**我们抽的是哪一层**：**属性声明化**（`lib/inspector-model.js`）——属性面板的字段不是手画的，是从声明里长出来的，含类型与校验。

**在 mini 里的意义**：给插件加一个新配置项，不用改面板代码；面板显示什么、怎么校验，都由声明决定。

## 7. amis —— JSON 配置的低代码前端（百度）

**它是什么**：用 JSON 描述一个后台页面（表格、表单、图表、弹窗），amis 负责渲染与交互。

**原本的核心功能**（✅）：

| 能力 | 说明 |
|---|---|
| 渲染器体系 | 每个 UI 组件是一个「渲染器」，按 type 匹配，可注册新渲染器 |
| 数据域 | 页面/组件有各自的数据作用域，表达式在域里求值 |
| 表达式 | `${...}` 在配置里做简单运算与取数据 |
| 事件与动作 | 组件事件 → 动作（请求、弹窗、跳转、刷新、自定义脚本），可带条件 |
| CRUD 快速成型 | 一份配置生成增删改查 |

**我们抽的是哪一层**：**事件钩子 before/after**（`lib/hooks.js` + `hook-rules.js`）。
关键设计：`before` 可以**拒绝**这次操作，但**必须给出理由**——理由会显示给用户，而不是静默失败。

**在 mini 里的意义**：批量改之前先过规则（比如「禁止一次停用超过 3 个插件」），被拦下时你知道为什么。

## 8. GrapesJS —— 网页构建器（只看思路）

**它是什么**：开源的可视化网页构建器，可嵌进 CMS/建站系统。

**原本的核心功能**（✅）：

| 能力 | 说明 |
|---|---|
| 组件模型 | 可嵌套的组件树，支持自定义组件类型与其「能不能放子元素」 |
| 块（Blocks） | 可拖入的预制块 |
| 样式管理器 | 直接编辑 CSS 规则（选择器 + 属性），不是内联样式 |
| 图层/大纲 | 结构视图，支持重排 |
| 命令 + 快捷键 | 所有操作注册为命令，快捷键只是命令的绑定，可重绑 |
| 插件体系 | 编辑器本身由插件拼起来 |

**为什么只取思路**：它是「网页编辑器」，我们是「插件治理」；但它的**命令分层**很值得学——
「做什么」与「怎么触发」分离。我们把设计器的操作也做成命令 + 导航动作两层，快捷键/按钮都只是绑定。

你说卖点是「**mini 这个环境做深层次工作 + 方便快捷的操作**」。把这九个机制翻译成用户能感知的话：

| **看「什么时候变的」**，而不只是「再退一步」 | Designable 历史时间线 | 历史面板 |
| **一次改 20 个插件** | LowCodeEngine 多选 | 插件页批量操作 |
| 新配置项**自动长出控件和校验** | LowCodeEngine Setter + Formily 声明化 | 属性面板 |

| 快捷键/按钮**只是命令的绑定** | GrapesJS 命令分层 | 设计器操作 |

## 10. 诚实边界

- 我们没有嵌入任何完整上游产品。**只抽机制，不留依赖**（除了 `es-module-lexer` / `acorn` 这类解析库）。
- ToolJet（AGPL）与 Budibase（BSL）**只读不抄**；GrapesJS Studio SDK 是收费产品，与本仓库无关。
- TreeNew 的源码已在 2026-10-31 逐行核对（见第 2 节与 docs/65）；其余项目仍按公开设计与文档复述，未逐行核对源码。
- 抽机制不等于照搬：我们的实现都按「harness 的行级 patch + 插件树」重写过，不是抄代码。
