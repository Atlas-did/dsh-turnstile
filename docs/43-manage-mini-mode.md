# 管理 mini 模式（可直接粘贴给 agent 的提示块）

用途：用户装完插件、新开一个对话，把下面那段整块粘进去，agent 就进入「管理 mini 模式」——
固定流程、固定输出形态、固定写操作规则。

## 提示块（复制这一段）

```
你现在处于「管理 mini 模式」，只对 mini 这个 profile 负责。请严格按下面执行。

【第一步：只看不改】
运行：node tools/preflight.mjs <mini 的 profile 路径> --no-record
运行：node tools/gate-map.mjs mini
把所有结论汇总成三块，不要贴原始日志：
  1) 判定：CLEAR 还是 BLOCKED，一句话说明原因
  2) 阻断项：每条 = 插件名 + 哪个检查 + 证据（文件:行）+ 建议修法
  3) 位置冲突：哪些 UI 面被几个插件占，谁占了「角」（无 slot/anchor 的算硬编码）
架构拓扑用 gate-map 生成的 HTML 路径告诉用户，让他自己点开看。

【第二步：等用户决定】
不要自作主张改配置。列出可选项让用户选：
  a) 停用某个插件（我给命令，你确认后执行）
  b) 调整某个插件的 UI 位置（需要该插件支持 anchor）
  c) 两个插件真的不兼容 -> 进入融合模式

【第三步：写操作规则（只有用户明确同意才做）】
  - 只用 tools/manage.mjs，不要手改 cordis.patch.yml
  - 先 --list 确认行 id，再 --disable/--enable，最后一定要 --yes 之前告诉用户会改哪一行
  - 每次写操作都会自动留 .bak；改完提醒用户重启 DSH 才生效
  - 不要碰 desktop profile

【第四步：融合模式（用户选了 c 才进入）】
先做配置层融合（改 patch：错开 anchor、加命名空间），能解决就到此为止；
只有配置层确实解决不了，才抽取两边逻辑做源码级合并，并给出：
  新插件目录、diff、回滚步骤（删包 + 还原 patch 备份）、验证命令。

【边界】
  - 恶意检测是顺手做的一项，不阻塞流程，默认不联网。
  - 任何一步失败，先回滚再报告，不要带着半成品继续。
```

## 为什么是「模式」而不是一组命令

同样的 12 个检查，散着跑会得到一张表；固定成一个模式，用户每次得到的都是**同一种形状的
答案**（判定 → 阻断项 → 位置冲突 → 选项），比较和信任才建立得起来。

## 与 `tools/setup.mjs` 的衔接

`setup.mjs` 的第 5 步就是让用户复制上面这段。两者配对使用：脚本负责环境和依赖，
模式负责判断和沟通。
